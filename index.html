Особенности

Компилируемый язык

Kotlin · компилируемый
исходный код→компилятор→байт-код JVM→запуск на JVM

Ошибки видны уже на этапе компиляции.

JavaScript · интерпретируемый
исходный код→движок, например V8, исполняет на лету (Just-In-Time)

Отдельного этапа сборки нет, ошибки видны только при выполнении.

Факт третий

Что убрали сознательно

Java

static int max(int a, int b) {
    return a > b ? a : b;
}
Kotlin

fun max(a: Int, b: Int) =
    if (a > b) a else b

Нет static, нет тернарного оператора, нет обязательного перечисления исключений, нет точки с запятой.

Плюс первый

Не позволяет забыть про пустоту

Тони Хоар придумал null в 1965 году и позже назвал это своей «ошибкой на миллиард долларов».

Фото: Wikimedia Commons
Плюс первый

NullPointerException

Java – всё выглядит нормально, пока не упадёт

String name = null;
System.out.println(name.length());
// NPE. Привет, выходные, мы ищем ошибку
Kotlin – не скомпилируется

val name: String = null   // ошибка компиляции
val name: String? = null  // явно nullable – окей
println(name?.length)     // null, не упадёт
println(name?.length ?: 0) // если null – вернёт 0
Плюс первый

В Kotlin String и String? – разные типы

Код, который лезет в пустоту без проверки, просто не соберётся.

1знак ? отличает тип, который может быть пустым

Недостатки Kotlin

Где Kotlin уступает вебу

Минус первый

iPhone – это отдельное приложение

  • Написанное для Android на iPhone не запускается
  • Автоматического перевода Kotlin → Swift нет
  • Нужен Mac: среда Apple работает только на нём

Ответ – Kotlin Multiplatform: общий код и общий интерфейс. Но проект нужно с самого начала строить под две платформы.

В вебе об этом не думаешь: ссылка открывается везде.

Минус второй

Нет немедленной обратной связи

Веб
написал код→увидел результат
Android
написал код→сборка→установка на телефон→дошёл до нужного экрана→увидел результат

Отличия телефонов значительнее, чем отличия браузеров

Батарея важнее приложения.

Строгий язык – страховка от ошибок агента

  • забыл проверить на пустоту → не собралось
  • не обработал новый вариант → не собралось
  • оставил лишнюю переменную → не собралось
  • подставил не тот тип → не собралось
  • нарушил границу слоёв → упал тест

Агент видит эти ошибки сразу и чинит сам. Чем строже компилятор, тем лучше с ним работает агент.

«Научитесь программировать за десять лет»

Бывший директор по исследованиям Google: мастерство в любой сложной области – это около десяти лет целенаправленной практики.

Это по-прежнему так. Но для создания приложения со средним уровнем сложности и ответственности мастерство в конкретном языке больше не обязательно: код пишет агент.

Задачи и решения остаются за человеком, который несёт ответственность за результат разработки.
